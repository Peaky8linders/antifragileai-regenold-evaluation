## A. Article 4 AI literacy — binds at ALL risk tiers (SHIPPED)

### Statute evidence (pinned corpus, `app/data/provision_text.py`)

> "Providers and deployers of AI systems shall take measures to ensure, to
> their best extent, a sufficient level of AI literacy of their staff and
> other persons dealing with the operation and use of AI systems on their
> behalf …"

Unqualified by risk tier, and it names exactly two roles: **provider** and
**deployer**. The pre-R371.8 matrix bound Art. 4 only at `MINIMAL_RISK` — a
legal **under-scope** mis-fact (the mirror of the R371.6 direction-inverted
removals).

### Change (matrix 74 → 80 bindings)

`Art. 4` added to: `PROVIDER × {high_risk_annex_i, high_risk_annex_iii,
limited_risk}` and `DEPLOYER × {high_risk_annex_i, high_risk_annex_iii,
limited_risk}` (MINIMAL already had it). Explicitly NOT added to:

- **GPAI / GPAI_SYSTEMIC** — Art. 4 names "AI systems"; the GPAI rows carry
  model-level duties (Art. 53/55 + Annexes XI–XIII).
- **PROHIBITED** — banned practices have no lawful provider/deployer relation.
- **Importer / distributor / AR / downstream / notified body / affected
  person** — Art. 4 names only providers and deployers.

### B.1 REAL BUG — the R362 request budget was keyed-but-dead

`_graph_rag_impl.py:10167` imports `reset_request_budget` from
`cohere_rerank`; the ImportError is swallowed by the fail-soft wrapper; and
`REGENOLD_RERANK_REQUEST_BUDGET` is read **nowhere** in `app/`. Verified by
direct import: `ImportError: cannot import name 'reset_request_budget'`.
The :3122 comment claimed "the per-request call budget now bounds this" —
false. The R350-documented 5-call cascade was **unbounded**, and the Trial key
(10 calls/min, 1,000/month) could 429 into a false INERT A/B — the precise
R350 trap, re-armed by a comment without code.

**Fix (shipped):** module-level `_budget_remaining` + `reset_request_budget()`
(fresh env read of `REGENOLD_RERANK_REQUEST_BUDGET`, default **2**), acquire
inside `rerank_documents` (the single network funnel — kb_search BM25 rerank,
parse-level pool rerank, kg-context rerank all pass through it), `None` =
unarmed = historical behaviour, `budget_blocked` stat counter. Reset wired at
the `ask_compliance_question` entry (the route calls it at regenold.py:7788).

### B.2 Rerank-v4.0 wiring (official-docs-driven)

Cohere best-practices + the v2 API reference: **rerank-v4.0-pro / -fast carry
a 32,768-token context** (docs chunk long docs at 32,764 tokens); the v2 API
truncates docs to `max_tokens_per_doc` (default 4096).

**Live probe (Trial key, 2026-08-18, 6 calls):** all three models answer on
this key.

| model | pool latency | raw latency | relevance scores (6-doc pool) |
|---|---|---|---|
| rerank-v3.5 | 0.50 s | 0.22 s | 0.90 / 0.87 / 0.85 / 0.75 / 0.71 / 0.63 |
| **rerank-v4.0-pro** | **0.32 s** | 0.27 s | **0.98 / 0.97 / 0.96 / 0.92 / 0.88 / 0.86** |
| rerank-v4.0-fast | 0.22 s | 0.24 s | 0.95 / 0.95 / 0.94 / 0.90 / 0.82 / 0.75 |

v4.0-pro: faster AND better-separated scores. **Shipped as the new default**
(`_DEFAULT_MODEL = "rerank-v4.0-pro"`; env `REGENOLD_COHERE_RERANK_MODEL`
overrides), plus:

- **Model-aware doc cap**: v3.x keeps 4,000 chars; v4.0 raises to 24,000
  chars (~6k tokens — a full EU AI Act provision fits in ONE 32,764-token
  chunk, so the cross-encoder sees the whole article).
- **`max_tokens_per_doc: 16384`** sent for v4.0 (half the context; the query
  takes the other half per best-practices) so the API never silently cuts a
  full provision.
- **`X-Client-Name: regenold-rag`** (docs-recommended attribution header).

**Trial-limit discipline:** budget 2 calls/request × ≤10/min = the A/B pacing
guidance in the review (`--min-call-gap 6.5`) is now consistent with the key's
real limits. The data-protection note in the module docstring was updated to
the new doc sizes.
