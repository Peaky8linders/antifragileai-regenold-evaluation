## Critical Issues

### [C1] Bedrock Default Model Alias Resolves to 403-Denied Model `claude-opus-4-8`
- **File:** `app/llm/bedrock_client.py:220`, `app/config.py:33`, `app/engines/_graph_rag_impl.py:500`
- **Bug:** Default alias `_resolve_default_model()` and `BEDROCK_MODEL_ALIASES["opus"]` point to `eu.anthropic.claude-opus-4-8`. On AWS Bedrock, this model ID returns `403 AccessDeniedException` under standard credentials, whereas active catalog models like `eu.anthropic.claude-opus-4-6-v1` work cleanly.
- **Impact:** Any out-of-the-box Bedrock completion call fails with 403 entitlement error and degrades to deterministic Stage-1 output.
- **Suggested fix:** Change default model aliases to point to active, verified catalog models: `eu.anthropic.claude-opus-4-6-v1` for Opus, `eu.anthropic.claude-sonnet-4-6` for Sonnet/Judge, and add fallback logic.
- **Confidence:** High (95%)
- **Found by:** Logic & Correctness, Contract & Integration

### [C2] CLI `--provider` Argument Parser Excludes `"bedrock"` in Judge Runners
- **File:** `evals/judge/runner.py:963`, `evals/judge/grounded.py:652`
- **Bug:** CLI `argparse` `choices` parameters in both `runner.py` and `grounded.py` excluded `"bedrock"` (permitting only `wrapper`, `anthropic`, `groq`, `gemini`).
- **Impact:** Executing legal judge benchmarks via CLI with `--provider bedrock` as documented crashes immediately with `argparse: invalid choice: 'bedrock'`.
- **Suggested fix:** Add `"bedrock"` to the `--provider` choices in both `runner.py` and `grounded.py`.
- **Confidence:** High (98%)
- **Found by:** Contract & Integration

### [C3] Response Attribute Mismatch (`prompt_tokens`/`completion_tokens`) in `BedrockResponse`
- **File:** `app/llm/bedrock_client.py:80-94`
- **Bug:** `BedrockResponse` provided `input_tokens` and `output_tokens`, whereas `OpenAIWrapperResponse` used `prompt_tokens` and `completion_tokens`. `thinking: str | None` was also absent.
- **Impact:** Calling `.prompt_tokens` or `.completion_tokens` on a `BedrockResponse` raises an unhandled `AttributeError` when duck-typing across provider responses.
- **Suggested fix:** Add property getters `@property def prompt_tokens(self) -> int:` and `@property def completion_tokens(self) -> int:` and `thinking: str | None = None` attribute to `BedrockResponse`.
- **Confidence:** High (95%)
- **Found by:** Contract & Integration, Logic & Correctness

### [C4] Bedrock Provider Complete Uncaught Exception Handling & Null Navigation
- **File:** `app/llm/bedrock_client.py:508-601`
- **Bug:** `_parse_converse_response` accessed nested keys assuming non-None objects, and `BedrockProvider.complete()` caught only `ClientError` and `BotoCoreError`.
- **Impact:** A null field in a Bedrock response payload raises `AttributeError`/`TypeError` which escapes `BedrockProvider.complete()` unhandled instead of returning a structured error response.
- **Suggested fix:** Use safe null navigation `(response.get("output") or {})` and wrap `BedrockProvider.complete()` in a top-level `try...except Exception as exc:` block.
- **Confidence:** High (90%)
- **Found by:** Error Handling, Contract & Integration

## Important Issues

### [I1] Unsynchronized `_TIMEOUT_CLIENTS` Dictionary Access Outside Lock
- **File:** `app/llm/bedrock_client.py:668`
- **Bug:** `_client_for_timeout` accessed `_TIMEOUT_CLIENTS.get(key)` outside `_TIMEOUT_CLIENT_LOCK` before double-checked locking.
- **Impact:** Dictionary rehashing during concurrent insertion can cause data races or `KeyError`/`RuntimeError` under concurrent FastAPI loads.
- **Suggested fix:** Move initial dictionary lookup inside `_TIMEOUT_CLIENT_LOCK`.
- **Confidence:** High (85%)
- **Found by:** Concurrency & State

### [I2] `_engine_cache_key` Omits Bedrock Model & Region Flags
- **File:** `app/routes/regenold.py:1350`, `app/engines/_graph_rag_impl.py:538`
- **Bug:** `_engine_cache_key` omitted `REGENOLD_BEDROCK_MODEL`, `BEDROCK_DEFAULT_MODEL`, and `BEDROCK_REGION` from the cache bit representation.
- **Impact:** Dynamic model A/B evaluation tests (`ab_judge`, Opus 4.6 vs Opus 5) serve cached responses from Arm A to Arm B, rendering the A/B test inert.
- **Suggested fix:** Include all Bedrock model and region environment variables in `_engine_cache_key`.
- **Confidence:** High (95%)
- **Found by:** Concurrency & State

### [I3] Bedrock RAG Completion Path Skips Verdict Truncation Guards
- **File:** `app/engines/_graph_rag_impl.py:568`
- **Bug:** `_bedrock_complete_for_graph_rag` omitted `_looks_incomplete_verdict(resp.text)` validation and `ReasoningTrace` logging present on the OpenAI wrapper path.
- **Impact:** Truncated Bedrock completions ending mid-reasoning pass as valid Stage-2 responses instead of falling back to deterministic Stage-1 output.
- **Suggested fix:** Add `_looks_incomplete_verdict` check and `ReasoningTrace` logging to `_bedrock_complete_for_graph_rag`.
- **Confidence:** High (90%)
- **Found by:** Error Handling, Logic & Correctness

### [I4] Judge Response Parsing & Unbalanced JSON Retryability
- **File:** `evals/judge/runner.py:153, 505`, `evals/judge/grounded.py:478`
- **Bug:** `"unbalanced_json"` was marked non-retryable in `is_retryable_judge_error`, strict `verd == "pass"` failed on `"pass."`, and single-span JSON parsing failed when leading text contained braces.
- **Impact:** Truncated or slightly formatted LLM judge responses were falsely categorized as unrecoverable errors.
- **Suggested fix:** Remove `"unbalanced_json"` from non-retryable list, strip trailing punctuation on verdict parsing, and adopt multi-span JSON extraction.
- **Confidence:** High (90%)
- **Found by:** Error Handling, Logic & Correctness

### [I5] In-Memory Evidence Store Eviction False Failure
- **File:** `app/evidence/store.py:302`
- **Bug:** `InMemoryAuditStore.verify_chain()` checked `rows[0].previous_hash != ""` starting from genesis. Once bounded deque evicted the genesis entry, verification failed falsely.
- **Impact:** Audit chain verification failed falsely under continuous production load.
- **Suggested fix:** Initialize `prev_hash = rows[0].previous_hash` when genesis is evicted.
- **Confidence:** High (90%)
- **Found by:** Concurrency & State
