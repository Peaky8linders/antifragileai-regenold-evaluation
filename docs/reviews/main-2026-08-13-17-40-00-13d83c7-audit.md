## Critical Issues

### [C1] The 403 fallback can never fire on the tier it was written for
- **File:** `app/engines/_graph_rag_impl.py:554-562`
- **Bug:** The fallback resolves its target as `resolve_bedrock_model("claude-opus-4-6")`
  → `"eu.anthropic.claude-opus-4-6-v1"`. The same diff sets
  `BEDROCK_RAG_MODEL = "eu.anthropic.claude-opus-4-6-v1"` (line 500). So for Stage-1 and
  Stage-2 — the exact tier the reported 403 was observed on — `model_id` and
  `fallback_id` are the identical string, the guard `if fallback_id != model_id:` is
  False, and the fallback is skipped.
- **Failure scenario:** Entitlement for `opus-4-6-v1` lapses, or an operator sets
  `REGENOLD_BEDROCK_MODEL=eu.anthropic.claude-opus-4-8` to restore the pinned target. The
  call 403s, the "automatic fallback" does nothing, and the request degrades to
  deterministic Stage-1 output — the precise outcome the fallback was added to prevent.
- **Impact:** A safety net that reads as present in code review and in the report, and is
  structurally incapable of executing. Only the `complex_question` tier (still
  `opus-5`) can ever reach it.
- **Suggested fix:** Replace the single-target guard with an ordered fallback **chain**
  that skips any candidate already attempted, so it is correct independent of what the
  default happens to be.
- **Confidence:** High (98%) — verified by reading `BEDROCK_MODEL_ALIASES` and
  `resolve_bedrock_model`.
- **Found by:** Logic & Correctness

### [C2] The e2e script and the engine now disagree about the complex tier
- **File:** `scripts/e2e_bedrock_rag_judge_test.py:46` vs `app/engines/_graph_rag_impl.py:503`
- **Bug:** The script's `COMPLEX_MODEL` was changed to `eu.anthropic.claude-opus-4-6-v1`,
  but the engine constant `BEDROCK_COMPLEX_MODEL` is **still**
  `eu.anthropic.claude-opus-5` — unchanged by this diff.
- **Failure scenario:** The e2e preflight invokes `opus-4-6-v1`, passes, and reports the
  Bedrock path healthy. Production then routes a `complex_question` to `opus-5`, which
  is the tier most likely to 403. The preflight cannot observe the failure it exists to
  catch.
- **Impact:** Textbook instrument trap (CLAUDE.md: "can this instrument physically
  observe the thing I am deciding?"). The green e2e run is not evidence about the tier
  that actually ships.
- **Suggested fix:** The e2e script must import the engine constants rather than
  re-declare them, so the two cannot drift.
- **Confidence:** High (95%)
- **Found by:** Contract & Integration, Plan Alignment

## Important Issues

- **File:** `app/engines/_graph_rag_impl.py:500`, `app/llm/bedrock_client.py:234,405,413`,
  `scripts/e2e_bedrock_rag_judge_test.py:45-47`

  `opus-4-8` (main RAG) / `opus-5` (complex) / `sonnet-5` (judge) as **code** defaults,
  and the deleted comment block explained *why* they are code defaults (`railway.toml
  [deploy.envs]` has never applied). The diff repoints the defaults and the `opus` /
  `sonnet` shorthands downward and removes that explanation.
- **Impact:** Production model selection changes without a recorded decision, and the
  rationale that would stop the next agent re-litigating it is gone. Note the alias map
  still carries `claude-opus-4-8` → `eu.anthropic.claude-opus-4-8`, so this is a change
  of *defaults*, not a loss of capability.
- **Countervailing evidence:** CLAUDE.md itself records that on 2026-08-11
  `claude-opus-4-8` returned `AccessDeniedException` on every invoke while

  policy fixed at creation and that console grants do **not** widen an existing key —
  i.e. the correct remedy may be re-minting the credential, not downgrading the fleet.
- **Suggested fix:** Operator decision required (see "Open decision" below). Whichever
  way it goes, restore the deleted rationale comment.
- **Confidence:** High (95%)
- **Found by:** Plan Alignment

## Verified as correct — keep

These claims were checked against real code and are sound. Recording them so they are
not re-litigated:

  specifically for the silent-fallback trap. `grounded.py:47` imports `_resolve_caller`
  from `runner.py`, which has genuine dispatch branches at `runner.py:611-614`
  (`_call_judge_gemini`, `_call_judge_bedrock`). The added choices reach real code.
- **[C4] Null-safe Converse parsing + catch-all `except Exception`.** Correctly placed
  *after* `ClientError` and `BotoCoreError` (`bedrock_client.py:614`), so classified
  errors keep their categories. Sound.
- **[I1] `_TIMEOUT_CLIENTS` lock.** Moving the first `.get` inside
  `_TIMEOUT_CLIENT_LOCK` is correct; the cost is one uncontended lock per call.
- **[I2] `_engine_cache_key` additions.** All six added vars are engine-level and belong
  in the key per CLAUDE.md's rule. Verified non-phantom:
  `REGENOLD_BEDROCK_STAGE1_MODEL` / `_STAGE2_MODEL` are really read at
  `_graph_rag_impl.py:536,538`. This closes the same defect class as R326/R327.
- **[I3] Verdict guard on the Bedrock path.** `REGENOLD_STAGE2_VERDICT_GUARD` already
  governs the wrapper path at `_graph_rag_impl.py:897`; the diff brings Bedrock to
  parity. Correct, and the right direction.
- **[I5] Evidence-store genesis eviction.** **Real bug, sound fix.** Confirmed
  `self._records: deque[EvidenceEntry] = deque(maxlen=max_records)` at
  `store.py:179` — genuinely bounded, so once genesis evicts, `rows[0].previous_hash`
  is non-empty and the old `prev_hash = ""` seed failed verification on healthy data.
  Tamper-evidence is preserved: row 0's payload is still hashed against its recorded
  `previous_hash`, and rows 1..n are unaffected.
- **`resolve_bedrock_model` passthrough.** No silent rewrite risk: full `eu.` profile IDs
  short-circuit at `bedrock_client.py:444` before the alias map.

## Suggestions

  never reads `reasoningContent` from the Converse payload. Dead field.

## Open decision (operator)

**Which Bedrock model targets ship?** The measured 403 on `opus-4-8` is real, but
CLAUDE.md indicates it may be a credential-vintage artefact rather than an account
block. The decisive instrument is an actual invoke with the *current* key — that probe
was proposed and declined, so this review cannot settle it. Options: (a) re-mint the
Bedrock key and keep the pinned targets, (b) accept the downgrade and update CLAUDE.md's
R328 section to match, or (c) keep pinned targets + a working fallback chain (C1) so the
system self-heals either way.
