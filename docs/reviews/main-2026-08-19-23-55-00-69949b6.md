A comprehensive multi-agent deep code review was conducted across the latest pushback optimization, Stage-2 OpenRouter primary routing, Bedrock Qwen judge, and XML channel separation implementations. ## Critical Issues

### [C1] `_stage2_provider_enabled` Omits `openai_wrapper` Match Before Fallback Cascade
- **File:** `app/engines/_graph_rag_impl.py:1741-1804`
- **Bug:** `_stage2_provider_enabled()` explicitly tests `cli`, `openrouter`, `groq`, `gemini`, `bedrock`, `anthropic`, but lacks an explicit `if env_value == "openai_wrapper": return is_openai_wrapper_enabled()`. When `P2P_GRAPH_RAG_PROVIDER="openai_wrapper"` is configured, execution falls into the `# auto / unset` cascade, checking `is_openrouter_provider_enabled()` and `is_bedrock_provider_enabled()` first.
- **Impact:** Any ambient OpenRouter or Bedrock API key in the environment causes Stage-2 to remain enabled even when `is_openai_wrapper_enabled` is patched to `False` or when the OpenAI wrapper is offline. This directly causes test suite failures in `tests/test_two_stage_pipeline.py` (`test_stage2_skipped_when_wrapper_disabled` and `test_stage2_call_failed_unset_when_wrapper_disabled`).
- **Suggested fix:** Add explicit check `if env_value == "openai_wrapper": return is_openai_wrapper_enabled()` before the fallback cascade.
- **Confidence:** High (95%)
- **Found by:** Logic & Correctness Specialist, Contract & Integration Specialist

### [C2] `test_every_alias_target_is_an_eu_profile` Fails on Qwen Model Aliases
- **File:** `tests/test_bedrock_client.py:928-932`
- **Bug:** `test_every_alias_target_is_an_eu_profile` asserts that every entry in `BEDROCK_MODEL_ALIASES` starts with `"eu.anthropic.claude"`. When `qwen.qwen3-32b-v1:0` and related Qwen aliases were added to `BEDROCK_MODEL_ALIASES` in `app/llm/bedrock_client.py`, the test was not updated.
- **Impact:** Fails `pytest tests/test_bedrock_client.py` with `AssertionError: ('qwen.qwen3-32b-v1:0', 'qwen.qwen3-32b-v1:0')`.
- **Suggested fix:** Update the assertion in `tests/test_bedrock_client.py` to differentiate Claude aliases (which must target `eu.anthropic.claude`) from non-Claude aliases (which target valid provider namespaces such as `qwen.`).
- **Confidence:** High (98%)
- **Found by:** Error Handling & Edge Cases Specialist, Contract & Integration Specialist

### [C3] XML Channel Hijacking & CoT Leakage in `extract_xml_channels`
- **File:** `app/security/prompt_guard.py:47-77`
- **Bug:**
  1. `_ANSWER_BLOCK_RE.finditer(text)` runs on unstripped `text` before `<reasoning>` blocks are removed. If an internal reasoning scratchpad quotes an `<answer>...</answer>` tag and the model outputs plain prose, the inner reasoning tag is extracted as the public answer.
  2. In the fallback branch (`else:`), line 75 computes `clean_answer = cleaned or text.strip()`. If the LLM generates only a `<reasoning>` block and no answer, `cleaned` becomes `""`, causing `clean_answer` to fall back to `text.strip()`, which leaks the raw `<reasoning>` block as the user answer.
  3. `<think>...</think>` tags are not captured in `extracted_reasoning`, losing thinking telemetry from open-reasoning models.
- **Impact:** Internal model reasoning and injected prompt tokens can hijack the user-facing answer field or leak internal CoT tokens to API clients.
- **Suggested fix:** Strip reasoning/think blocks first before searching for `<answer>` tags, prevent fallback to unstripped `text.strip()` when `cleaned` is empty, and extract `<think>` blocks into `extracted_reasoning`.
- **Confidence:** High (95%)
- **Found by:** Security & Regulatory Specialist, Logic & Correctness Specialist, Error Handling & Edge Cases Specialist

### [C4] Dict Message Type Incompatibility in History Helpers Disables Pushback Reference Freezing
- **File:** `app/routes/regenold.py:4307-4315`, `6657-6659`, `6954-6955`, `7420-7423`
- **Bug:** `_last_assistant_content` uses `getattr(msg, "role", None) == "assistant"`. When messages are Python dicts (e.g. `{"role": "assistant", "content": "..."}`), `getattr` returns `None`. Similarly, `_extract_conversation_anchors` and `_looks_like_scenario_shape` use `getattr(turn, "role", "")` and `turn.content`.
- **Impact:** For dict messages, `_last_assistant_content` returns `""`, which silently disables `_freeze_refs_to_prior_turn` at line 10646, bypassing reference freeze protection on adversarial challenge turns. Additionally, conversation anchors are dropped and scenario detection fails.
- **Suggested fix:** Use dict-safe accessors (`msg.get("role") if isinstance(msg, dict) else getattr(msg, "role", None)`) across all history and turn extraction helpers.
- **Confidence:** High (95%)
- **Found by:** Logic & Correctness Specialist, Error Handling & Edge Cases Specialist

### [C5] `_call_judge_anthropic` Sends Invalid Default Model `qwen.qwen3-32b-v1:0` to Anthropic API
- **File:** `evals/judge/runner.py:565`
- **Bug:** When `_DEFAULT_JUDGE_MODEL` was changed to `"qwen.qwen3-32b-v1:0"`, `_call_judge_anthropic` was left passing `model=_JUDGE_MODEL` directly to `client.messages.create(...)` without checking if `_JUDGE_MODEL == _DEFAULT_JUDGE_MODEL`.
- **Impact:** Running `python -m evals.judge.runner --provider anthropic` without `--model` sends Qwen model names to Anthropic, causing 100% of rows to fail with API model errors.
- **Suggested fix:** Add standard provider fallback resolution: `model = _JUDGE_MODEL if _JUDGE_MODEL and _JUDGE_MODEL != _DEFAULT_JUDGE_MODEL else "claude-sonnet-5"`.
- **Confidence:** High (95%)
- **Found by:** Concurrency & State Specialist, Logic & Correctness Specialist

### [C6] Pushback Early Returns Bypass Question Length and Context Truncation
- **File:** `app/routes/regenold.py:7368-7374`, `7302-7308`
- **What's wrong:** In `_build_question_from_history`, the challenge recovery block and re-ask block execute immediate `return QuestionHistoryResult(...)`, bypassing the 64,000-character question truncation and 1,000-character system context truncation at lines 7487–7510.
- **Impact:** Multi-turn adversarial dialogues can bypass token safety limits, resulting in unbounded prompt sizes sent to Stage 1 and Stage 2 models.

- **Found by:** Logic & Correctness Specialist

## Important Issues

### [I1] CLI `--provider wrapper` Hijacked by `P2P_GRAPH_RAG_PROVIDER=bedrock` Environment Variable
- **File:** `evals/judge/runner.py:846-851`
- **Bug:** `if provider == "bedrock" or os.getenv("P2P_GRAPH_RAG_PROVIDER", "").strip().lower() == "bedrock":` routes calls to Bedrock even when the CLI caller explicitly specified `--provider wrapper`.
- **Impact:** Command-line provider flags are overridden by ambient `.env` variables.
- **Suggested fix:** Only check `P2P_GRAPH_RAG_PROVIDER` when `provider in ("", "auto")`.
- **Confidence:** High (90%)
- **Found by:** Logic & Correctness Specialist, Contract & Integration Specialist

### [I2] `_stage2_complete` Dispatches to OpenAI Wrapper Under `provider=cli`
- **File:** `app/engines/_graph_rag_impl.py:1453-1523`
- **Bug:** `_stage2_complete` lacks a check for `resolved_p == "cli"`, falling through to `_openai_wrapper_complete_for_graph_rag`.
- **Impact:** Auxiliary calls (e.g. truncation repair, faithfulness check) make external network calls when the system is configured in strict offline/deterministic `cli` mode.
- **Suggested fix:** Add `if resolved_p == "cli": return None` at the top of `_stage2_complete()`.
- **Confidence:** High (95%)
- **Found by:** Contract & Integration Specialist

### [I3] `_aggregate_judge` Crashes on Boolean Verdicts and Formatted Strings
- **File:** `evals/judge/runner.py:964`
- **Bug:** `verdict = (v.get("verdict") or "").lower()` crashes with `AttributeError` if the LLM emits a boolean `{"verdict": true}`. It also fails to match `"pass."` or `"Pass "`.
- **Impact:** Crashes evaluation metric aggregation runs or inflates error counts.
- **Suggested fix:** Safely normalize `raw_v = v.get("verdict")` checking `isinstance(raw_v, bool)` and `.strip().rstrip(".").lower()`.
- **Confidence:** High (95%)
- **Found by:** Error Handling & Edge Cases Specialist

### [I4] `_freeze_refs_to_prior_turn` Freezes Against Raw Prose Instead of Filtered Wire Citations
- **File:** `app/routes/regenold.py:4259-4305`
- **Bug:** `_freeze_refs_to_prior_turn` extracts allowed articles from the entire raw prose of the prior assistant turn (`extract_referenced_articles(prior_assistant_text)`), which often contains background mentions not present in Turn 1's wire references.
- **Impact:** Allows citation set expansion on pushback turns. In `live_01_gpai_transparency`, Turn 1 cited 4 articles while Turn 3 expanded to 7 articles, causing `reference_correctness_strict` to collapse from 0.667 to 0.286.
- **Suggested fix:** Restrict `allowed` to citations that were present in the prior turn's wire references.
- **Confidence:** High (90%)
- **Found by:** Security & Regulatory Specialist
